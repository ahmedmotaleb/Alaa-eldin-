# تطبيق أندرويد (TWA) — توثيق البناء والنشر

## الفكرة المعمارية

التطبيق ده **مش** تطبيق أندرويد أصلي منفصل، ومش Capacitor (كان فيه واحد قبل كده اتشال
عمداً في commit `7e787c9` — "PWA only going forward"). ده **TWA** (Trusted Web Activity):
غلاف Android رفيع بيفتح متجر علاء الدين الحقيقي (نفس الدومين، نفس الـ cookies، نفس الـ
service worker) جوه تبويب Chrome موثوق بملء الشاشة. **مفيش أي كود منفصل أو نسخة تانية من
المتجر** — أي تغيير عادي على الموقع (منتجات/أسعار/checkout) بيظهر فوراً من غير أي APK جديد.

## الهوية الثابتة (لازم تتحافظ عليها في كل تحديث مستقبلي)

| Signing key alias | `alaa-eldin` |
| نوع المفتاح | RSA 4096-bit, PKCS12, صالح 30 سنة (٢٠٢٦-٢٠٥٦) |
| SHA-256 fingerprint | `19:F7:52:0F:00:1E:7F:29:D9:F1:35:CC:11:C1:09:42:F8:75:3D:DC:30:16:13:EA:EA:A7:D3:07:18:70:C6:6A` |
| Manifest URL | `https://alaa-eldin-production.up.railway.app/manifest.webmanifest` |
| assetlinks.json | `https://alaa-eldin-production.up.railway.app/.well-known/assetlinks.json` |

**تحذير حرج**: فقدان ملف الـ keystore (`alaa-eldin-release.keystore.jks`) أو كلمة السر
بتاعته يعني **مفيش أي إصدار مستقبلي هيقدر يتثبت فوق النسخة الحالية عند أي مستخدم** — لازم
حذف التطبيق يدوياً من كل جهاز وتثبيت نسخة جديدة بمفتاح مختلف من الصفر. احتفظ بنسخة من
الـ keystore وكلمة سره في **مكانين آمنين منفصلين على الأقل** (مدير كلمات سر + نسخة
احتياطية مشفّرة منفصلة). **الملف ده أبداً ما يتحطش في Git.**

## أين يعيش المفتاح فعلياً

- تم توليده مرة واحدة (RSA 4096، `keytool`) وأُرسل مباشرة لصاحب المشروع كملف — مفيش نسخة
  منه محفوظة في أي مكان تاني بمعرفتنا.
- مخزّن في GitHub Actions repository secrets (Settings → Secrets and variables → Actions):
  - `ANDROID_KEYSTORE_BASE64` (محتوى الملف بصيغة base64)
  - `ANDROID_KEYSTORE_PASSWORD`
  - `ANDROID_KEY_ALIAS` (= `alaa-eldin`)
  - `ANDROID_KEY_PASSWORD` (نفس قيمة `ANDROID_KEYSTORE_PASSWORD` — كلمات سر PKCS12
    الموحّدة بين الـ store والـ key)
- **مفيش ولا واحدة من القيم دي في الكود، في الـ workflow نفسه كنص صريح، أو في تاريخ Git.**

## ليه البناء الفعلي بيحصل على GitHub Actions مش محلياً

بيئة التطوير اللي استُخدمت لإعداد المشروع ده محجوب فيها الوصول لخوادم Android SDK
(`dl.google.com`) بسياسة شبكة صريحة — نفس القيد المكتشف سابقاً مع دومين الإنتاج نفسه.
GitHub Actions (`ubuntu-latest`) عنده Android SDK وJDK مُثبّتين مسبقاً ووصول شبكة كامل،
فده المكان الصحيح لتشغيل `bubblewrap init`/`build` فعلياً، مش قيد اصطناعي.

## بناء إصدار جديد (Workflow: `.github/workflows/android-apk-release.yml`)

1. من تبويب **Actions** في المستودع، اختار workflow اسمه **"Android TWA APK Release"**.
2. اضغط **Run workflow**، واملأ:
   - `versionName`: مثال `1.0.1` (اسم ظاهر للمستخدم)
   - `versionCode`: رقم صحيح **أكبر من آخر إصدار منشور** (مثال: لو آخر واحد كان `1`،
     التالي `2`) — Android بيرفض أي تحديث بنفس الرقم أو أقل.
3. الـ workflow بيعمل تلقائياً:
   - يتأكد إن الأسرار الأربعة موجودة (بيفشل بوضوح لو ناقصة، **من غير** ما يرجع لتوقيع
     debug بصمت)
   - `bubblewrap init` من manifest الإنتاج الحقيقي
   - يضبط `packageId`/`appVersionName`/`appVersionCode`/مسار مفتاح التوقيع
   - `bubblewrap build` (بناء + توقيع فعلي بالـ keystore)
   - يتحقق إن التوقيع **مش** debug (`apksigner verify`)
   - يحسب SHA-256 للملف النهائي
   - يرفع الـ APK كـ workflow artifact **و** كـ GitHub Release باسم `android-v<versionName>`

## بعد نجاح الـ workflow

1. افتح صفحة الإصدار (Release) اللي اتعملت، وتأكد إن ملف `.apk` وملف `.sha256` موجودين.
2. حدّث `CURRENT_VERSION` في `src/pages/DownloadPage.tsx` ليطابق `versionName` الجديد،
   وادفع (`git push`) — ده بيحدّث رابط التحميل في صفحة `/download` تلقائياً.
3. اختبر التثبيت فعلياً على **جهاز أندرويد حقيقي** (راجع القسم التالي) — مش محاكي، ومش
   متصفح كمبيوتر.
4. سيب الإصدار القديم متاح في GitHub Releases (للرجوع إليه أو التحقق التاريخي)، مش
   ضروري تمسحه.

## قاعدة التحديثات المستقبلية (غير قابلة للتفاوض)

- **نفس Package ID** (`com.alaaeldin.supermarket`) في كل مرة — تغييره يعني تطبيق مختلف
  تماماً من وجهة نظر Android (المستخدمين الحاليين مش هيستقبلوا تحديث، هيحتاجوا تثبيت جديد
  منفصل).
- **نفس مفتاح التوقيع** في كل مرة — استخدام مفتاح مختلف يخلي Android يرفض التحديث برسالة
  "App not installed — signature mismatch" فوق أي تثبيت حالي.
- `versionCode` الجديد **لازم يكون أكبر** من كل إصدار سابق (رقم صحيح بسيط، مش مرتبط
  بـ `versionName`).

## امتى تحتاج فعلاً تبني APK جديد

**مش محتاج APK جديد** لأي تغيير عادي في الموقع (منتجات، أسعار، عروض، checkout، أي صفحة) —
ده كله بيظهر فوراً لأن التطبيق بيفتح الموقع الحقيقي مباشرة.

**محتاج APK جديد فقط** لو اتغيّر:
- أيقونة التطبيق أو اسمه الظاهر
- إعدادات TWA نفسها (الألوان، الـ scope، السلوك)
- أي بيانات وصفية على مستوى Android (permissions مثلاً)

## تحذير أمني إضافي — لا يوجد أي سر إنتاجي جوه الغلاف نفسه

الغلاف (TWA) بتاع Android **مفيهوش أي إعدادات سيرفر حساسة على الإطلاق** — لا
`DATABASE_URL`، لا Meta access token، لا Cloudinary secret، لا Turnstile secret، لا VAPID
private key، لا بيانات اعتماد أدمن، ولا كلمة سر الـ keystore نفسه. كل ده منطقياً مش ممكن
يوصل للـ APK أصلاً لأن التطبيق بيعرض بس صفحة ويب عادية (الموقع الحقيقي) — نفس ضمانات أي
متصفح عادي بيفتح نفس الموقع.

## الاختبار الحقيقي على جهاز أندرويد (لازم، مش اختياري)

**تحذير**: لا يجوز اعتبار أي من الخطوات دي "تمت" بدون جهاز أندرويد حقيقي فعلي — محاكاة
متصفح كمبيوتر (Chromium desktop) **لا تُعتبر بديلاً** ولا دليل كافٍ.

1. امسح أي نسخة تجريبية قديمة لو موجودة
2. افتح `/download` على الموقع الرسمي من متصفح الجهاز
3. حمّل الملف
4. اسمح لـ Chrome بتثبيت تطبيقات خارجية لو Android طلب كده
5. اضغط تثبيت
6. افتح التطبيق وتأكد من: الأيقونة، الاسم بالعربي، ملء الشاشة (من غير شريط عنوان Chrome
   لو Digital Asset Links اتحقق صح)
7. تصفّح منتجات، أضف للسلة، جرّب واجهة الدفع
8. جرّب زر الرجوع (back) وإعادة فتح التطبيق بعد إغلاقه
9. جرّب رابط خارجي (واتساب/اتصال) وتأكد إنه بيفتح بره التطبيق صح
